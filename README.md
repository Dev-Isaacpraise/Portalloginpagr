# Credential Verification Portal for Academic Recruitment
### Final-Year Thesis Implementation: Multi-Factor Authentication (MFA) using RFC 6238 TOTP

This application demonstrates a production-grade **Multi-Factor Authentication (MFA)** system using **Time-based One-Time Passwords (TOTP)**, framed within an institutional credential verification portal for academic recruitment (Federal University Lokoja).

---

## 🏛️ Architectural Overview

The authentication pipeline separates identity verification into two distinct cryptographic phases:

1. **Step 1: Primary Authentication ("Something You Know")**
   - Candidate provides `username` and `password`.
   - The password is authenticated against an asynchronous **bcrypt** hash (work factor 10).
   - **Crucial Security Boundary**: Passing Step 1 **never** issues an authenticated session token. Instead, the user transitions to a temporary pending state (`mfaPendingUser`).

2. **Step 2: Time-based One-Time Password Verification ("Something You Have")**
   - The user inputs a 6-digit dynamic code generated by their mobile authenticator app.
   - Built on the **RFC 6238** standard:
     $$\text{TOTP} = \text{Truncate}(\text{HMAC-SHA-1}(K, C))$$
     Where $K$ is the Base32 shared secret, and counter $C = \lfloor(T - T_0) / T_X\rfloor$ with standard step $T_X = 30$ seconds.
   - A drift tolerance window of $\pm 1$ step accounts for natural network latency or mobile clock skew.
   - **Only upon successful verification is an authenticated session established**, unlocking the recruitment dashboard.

3. **Defense in Depth & Security Monitoring**
   - **Rate Limiting**: Throttles failed attempts (5 failures per 15-minute cooldown window per IP) to prevent automated token enumeration attacks on the 6-digit search space ($10^6$ combinations).
   - **Security Audit Logging**: Every authentication event (Step 1 and Step 2, successes and failures) is logged with timestamp, IP address, user-agent, and failure causes.

## 📂 Project Directory Structure

```
├── controllers/
│   ├── auth.controller.ts      # Primary login (step 1), registration & logout
│   ├── mfa.controller.ts       # Secret generation, QR codes, activation & TOTP verify (step 2)
│   └── portal.controller.ts    # Session-gated dashboard & academic credential verification
├── models/
│   ├── db.ts                   # SQLite3 connection, schemas & initialization
│   ├── user.model.ts           # User persistence & Base32 secret management
│   ├── loginAttempt.model.ts   # Granular authentication audit logs
│   └── academicRecord.model.ts # Candidate degrees, transcripts & verification hashes
├── middleware/
│   ├── auth.middleware.ts      # Session guard & transitional MFA state gates
│   └── rateLimiter.ts          # Brute-force throttling middleware
├── routes/
│   ├── auth.routes.ts          # POST /register, POST /login, GET /logout
│   ├── mfa.routes.ts           # POST /mfa/setup, POST /mfa/confirm, POST /mfa/verify
│   └── portal.routes.ts        # GET /dashboard
├── views/
│   ├── partials/               # Reusable header and footer EJS templates
│   ├── login.ejs               # Step 1 login with institutional university branding
│   ├── register.ejs            # Candidate registration form
│   ├── mfa-setup.ejs           # QR code scan, Base32 key fallback, 6-digit activation
│   ├── mfa-verify.ejs          # Step 2 verification with live 30s epoch countdown
│   └── dashboard.ejs           # Recruitment dossier, verified records & login audit panel
├── public/
│   ├── css/style.css           # Institutional academic styling system (self-contained plain CSS)
│   └── js/main.js              # 6-digit box auto-focus/paste sync & live TOTP clock
├── server.ts                   # Express server entry point
├── package.json
└── README.md
```

## 🚀 Quickstart & Local Setup

### 1. Prerequisites
- **Node.js** (v18 or newer)
- **npm** (v9 or newer)

### 2. Installation
Clone or navigate to the project directory, then run:

```bash
npm install
```

### 3. Running the Server
Start the portal in development mode:

```bash
npm start
# or
npm run dev
```

Open your browser and navigate to:
```
http://localhost:3000
```

### Scenario B: Testing MFA Enrollment & QR Code Activation

1. Sign in with the un-enrolled demo candidate:
   - Username: `new_applicant`
   - Password: `Password123!`
2. The portal detects `mfa_enabled = 0` and redirects to `/mfa/setup`.
3. **Scan the QR Code** with your mobile phone camera using:
   - Google Authenticator
   - Microsoft Authenticator
   - 2FAS Authenticator
   - Bitwarden / 1Password
4. Alternatively, copy the Base32 manual key.
5. Enter the generated 6-digit code in the spaced digit boxes.
6. Click **Confirm & Activate Multi-Factor Authentication**.
7. The secret is promoted to active in SQLite (`mfa_enabled = 1`), and the user is redirected to the verified candidate dashboard.

---

### Scenario C: Demonstrating Brute-Force Rate Limiting

1. Enter an incorrect password on `/login` or an incorrect 6-digit code on `/mfa/verify`.
2. Notice the inline error message and inspect the **Security Audit Table** on the dashboard to show that the failure was recorded with IP and timestamp.
3. Attempting 5 consecutive invalid entries triggers a `429 Too Many Requests` lockout for 15 minutes, protecting against dictionary enumeration.
